# HLstatsX: Curated Edition — upstream review

Review date: 2026-10-30. The working baseline is local commit `4b2d7c4` (app 1.11.6, DB95). Upstream heads and metadata were checked through the GitHub API; changes were evaluated against the local PHP/Perl architecture and existing Auto Team Balance, plugins, and UI behavior. This is a selective curation, not a merge of divergent histories.

## Curated release line

- App version: **1.13.0-CE**, aligned with the highest compatible community app-version lineage observed at NiDE-gg `df9dcaae` (1.13.0). The suffix distinguishes this curated build.
- Shared legacy database base: **DB96**. The PHP/Perl line remains DB96 and its updater history is retained through DB96. The separate Laravel frontend advances official DB96 installations to DB97 through its own migrations; this does not claim Lovasatt DB99 or NiDE DB120 compatibility.
- Existing sites must run the web updater before relying on DB96 settings/indexes. The updater is retryable and preserves custom server secrets, map calibrations, wider GeoIP columns, and existing data. No production database was touched.

## Backend modernization decision

- The current `dev` checkout is clean at `4b2d7c4`; the curated branch has the same base. It already contains the recent ATB work, including `b757551` (“use roster event time for settle checks”). The SourceMod ATB additions from the canonical `lama-srcds` checkout are included in `hlstatsx.sp`: live team-count reporting, round-end swap queueing, churn invalidation, safe prestart revalidation, and opt-in audit diagnostics. Daemon-side ATB policy and the API protocol remain unchanged.
- The imported ATB branches are explicitly guarded by `gamemod == Game_CSS`; round hooks and CSS team-count reads only run for Counter-Strike: Source, and the daemon invokes the ATB count/swap extension only for CSS. Other games retain the existing swap behavior and do not consume `hlx_atb_audit` or CSS economy/C4 diagnostics. The shared game plugin's general KD/join-policy native is retained separately from CSS round balancing.
- The companion `hlstatsx_kd.inc` public include is included so dependent SourceMod plugins can declare the custom KD natives. `HLX_KD_GetClient` is independent of round balancing; `HLX_GetPreferredTeam` is explicitly a CSS T/CT join-policy API and must not be applied to games with different team IDs.
- The public product identity is **HLstatsX: Curated Edition 1.13.0-CE** across frontend/database, daemon output, both CS:S/general and CS:GO game-plugin version fields, Docker examples, and release docs. The supported upgrade input is DB96 and Laravel migrations advance it to DB97; existing deployments get the default product label only when their configured name is still the stock upstream label.
- A1mDev's PDO/DI work remains a useful historical reference, not an implementation adopted by the Laravel frontend. It added a parallel PDO connection and began moving selected legacy routes into repositories.
- The daemon-side bounded high-traffic improvement (optional counter writes) retains its retry-safe DB96 setting and historical default. Laravel is a separate frontend/schema; preserve its DB97 gate and the independent Perl daemon protocol.

## Verification and known gaps

- Historical DB96 updater tests and legacy PHP lint results are recorded as pre-cutover evidence. Current tests cover Laravel migration guards/account behavior, route smoke checks, PHP 8.5 heatmap compatibility, and Perl ATB, swap, timestamp, and API behavior.
- Production Laravel root and route behavior are verified by the deployment helper; public route errors remain deployment blockers. A complete plugin/game compatibility suite and interactive visual review remain separate work.
- Both general SourceMod and CS:GO plugins compile to nonempty artifacts with SourceMod 1.13.0. CS:GO compilation retains seven pre-existing macro/deprecation warnings; no compiled artifacts were written into the repository.
- Laravel CSRF protection covers mutating admin forms and logout. The integration suite runs in a dedicated Compose project; plugin/game validation remains separate.
- Curated light/dark and System (auto) styles are opt-in in the existing selector, validated as local CSS filenames, and applied to in-game pages from the same visitor preference. System (auto) follows `prefers-color-scheme`; responsive viewport metadata is emitted only for curated themes, leaving classic theme behavior unchanged.
- Server/player location maps now use Leaflet with OpenStreetMap tiles, retaining the existing map visibility and region preferences without requiring a Google API key or DB migration. OSM attribution is displayed; deployments depend on external tile access and must respect the public tile service usage policy. The Compose example retains its default CS 1.6 service and offers an optional CS:S log-forwarding profile; the image does not include the curated SourceMod plugin.
- Laravel serves its native sitemap, APIs, maps, account/admin workflows, charts, and editable page routes; the application remains gated to DB97. The Perl daemon continues to supply the existing persisted gameplay/statistics data.
