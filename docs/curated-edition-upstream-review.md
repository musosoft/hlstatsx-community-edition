# HLstatsX: Curated Edition — upstream review

Review date: 2026-10-25. The working baseline is local commit `4b2d7c4` (app 1.11.6, DB95). Upstream heads and metadata were checked through the GitHub API; changes were evaluated against the local PHP/Perl architecture and existing Auto Team Balance, plugins, and UI behavior. This is a selective curation, not a merge of divergent histories.

## Curated release line

- App version: **1.13.0-CE**, aligned with the highest compatible community app-version lineage observed at NiDE-gg `df9dcaae` (1.13.0). The suffix distinguishes this curated build.
- Database version: **96**. It intentionally does not claim Lovasatt DB99 or NiDE DB120: their migration chains contain broader engine, key, schema, and feature changes that have not been proven safe against this checkout. This release adds only the verified local DB96 migration.
- Existing sites must run the web updater before relying on DB96 settings/indexes. The updater is retryable and preserves custom server secrets, map calibrations, wider GeoIP columns, and existing data. No production database was touched.

## Backend modernization decision

- The current `dev` checkout is clean at `4b2d7c4`; the curated branch has the same base. It already contains the recent ATB work, including `b757551` (“use roster event time for settle checks”). The SourceMod ATB additions from the canonical `lama-srcds` checkout are included in `hlstatsx.sp`: live team-count reporting, round-end swap queueing, churn invalidation, safe prestart revalidation, and opt-in audit diagnostics. Daemon-side ATB policy and the API protocol remain unchanged.
- The imported ATB branches are explicitly guarded by `gamemod == Game_CSS`; round hooks and CSS team-count reads only run for Counter-Strike: Source, and the daemon invokes the ATB count/swap extension only for CSS. Other games retain the existing swap behavior and do not consume `hlx_atb_audit` or CSS economy/C4 diagnostics. The shared game plugin's general KD/join-policy native is retained separately from CSS round balancing.
- The companion `hlstatsx_kd.inc` public include is included so dependent SourceMod plugins can declare the custom KD natives. `HLX_KD_GetClient` is independent of round balancing; `HLX_GetPreferredTeam` is explicitly a CSS T/CT join-policy API and must not be applied to games with different team IDs.
- The public product identity is **HLstatsX: Curated Edition 1.13.0-CE** across web/database, daemon output, both CS:S/general and CS:GO game-plugin version fields, Docker examples, and release docs. Schema remains DB96. Existing deployments get the new default label only when their configured name is still the stock upstream label; custom site names are preserved.
- A1mDev's PDO/DI work is a useful modernization direction, not a replacement backend that can safely be copied in. It adds a parallel PDO connection and begins moving selected routes into repositories while the legacy application still has extensive global mysqli/query usage, including direct `mysqli_*` consumers. Porting only the bootstrap would create two database stacks without completing prepared-statement coverage; replacing the wrapper at once would risk result-count, pagination, transaction, and admin-tool behavior.
- This release adopts the bounded high-traffic improvement (optional counter writes) with a retry-safe DB96 setting and historical default. A full PDO/repository transition should be a separately validated migration: keep the MySQL schema and old routes working, convert one route at a time with rendered-result/query tests, measure connection/query behavior, and retain an explicit rollback path. The Laravel repository is a separate frontend/schema migration, not a drop-in backend for this release.

## Verification and known gaps

- `test/test_updater96.php` exercises a failed migration followed by retry, repeated-run idempotency, index creation, version update, stock-name upgrade/custom-name preservation, preserved rows/secrets/calibration, GeoIP data, and the default-enabled counter setting in isolated MySQL 5.7.
- All 216 PHP application files pass `php -l` in the project PHP container; CSRF/password, theme-selection, and PHP compatibility tests pass there. `test/test_themes.php` verifies curated styles reach in-game pages and invalid cookie paths fall back to the classic stylesheet. Changed Perl files pass syntax checks in the daemon container; focused ATB, swap, timestamp, and API tests pass.
- No live site or production database was accessed. Full web route/browser testing and a complete plugin/game compatibility suite remain outstanding.
- Both general SourceMod and CS:GO plugins compile to nonempty artifacts with SourceMod 1.13.0. CS:GO compilation retains seven pre-existing macro/deprecation warnings; no compiled artifacts were written into the repository.
- The CSRF protection covers the current mutating admin POST forms and logout; full interactive route/browser validation remains outstanding. The repository's standard Compose test runner starts a game server and its init service recursively changes permissions on the mounted source tree, so it was not run against this worktree; no production or canonical checkout was touched.
- Curated light/dark styles are opt-in in the existing style selector, validated as local CSS filenames, and applied to the in-game header from the same visitor preference. Responsive viewport metadata is emitted only for these themes, leaving classic theme behavior unchanged.
- Server/player location maps now use Leaflet with OpenStreetMap tiles, retaining the existing map visibility and region preferences without requiring a Google API key or DB migration. OSM attribution is displayed; deployments depend on external tile access and must respect the public tile service usage policy. The Compose example retains its default CS 1.6 service and offers an optional CS:S log-forwarding profile; the image does not include the curated SourceMod plugin.
- Adopted the Laravel fork's low-risk SEO sitemap idea in the legacy router: `/sitemap.xml` emits the configured frontend URL and per-game player/clan/server/map/award listings. It does not require a schema migration and is excluded from the historical query cache. Broad feature parity is not claimed: Steam-linked accounts, editable content pages, live-feed/API endpoints, and Laravel admin workflows need individual compatibility/security review; several stats/admin/map capabilities already exist in the legacy app.
- Adapted Royal Laravel's public server-marker endpoint (`MapController::markers`, checked head `5e43cbfa167bb9ed8d21b4feaf69858fc2227d0c`) into `hlstats.php?mode=api_map_markers[&game=...]`. It is read-only, emits only public server fields, validates coordinates/game identifiers, and uses a 5-minute online threshold; no schema or daemon changes are needed. This is a narrow compatibility adaptation, not a copied Laravel controller or a promise of a versioned external API.

### Laravel readiness assessment (Royal-Multi-Gamers, head `5e43cbf`)

- **Not ready as a replacement for this curated deployment.** It is a substantial Laravel 13 frontend rebase, not a drop-in upgrade. The README's requirements conflict (`PHP 8.2+` and `PHP 8.5+`) with `composer.json`'s actual `^8.3` constraint; validate the exact PHP, Composer, Node, Redis, and MySQL matrix before deployment.
- Its own setup script runs `php artisan migrate --force`; migrations create Laravel support tables and apply HLstats option/game migrations. That is not a no-schema-change cutover, despite the README's broad statement that the HLstats schema is never modified. Test against a disposable copy of the actual DB96 database, including case-sensitive MySQL table names and the legacy daemon's option writes.
- The README correctly warns that the unauthenticated install wizard can create a superadmin and rewrite `.env`; `.env.example` defaults `APP_INSTALLED=false`, and setup does not itself seal it. Deployment needs a fail-closed install lock, secret/config ownership review, and tested rollback before exposure.
- The repo advertises frontend/admin features and has focused Laravel feature tests, but the review found no project-specific build/test CI workflow beyond CodeQL and release packaging. It also pairs Perl daemon sources from a different fork. Preserve the curated Perl daemon, DB96 migrations, CSS-only ATB implementation, SourceMod plugins, themes, and deployment behavior unless those are separately ported and proven.
- A safe path is a staged side-by-side web migration against a cloned database: run the Laravel test suite and production build, compare representative public/admin routes and writes against the current frontend, verify daemon interoperability and migration reversibility, then canary before any cutover. Until those gates pass, treat it as a promising development branch, not production-ready for this installation.
